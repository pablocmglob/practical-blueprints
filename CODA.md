# CODA.md — harness-specific notes

@import AGENTS.md

Everything normative lives in AGENTS.md and `.agents/rules/`. This file adds
ONLY what is specific to running agents inside CODA. Never duplicate a rule
here; edit it in AGENTS.md.

## Escalating a call within the agent network

- Sub-agents are launched with the `run_agent` tool; pass the configured
  agent `name` (see `.coda/agents/`). All agents use the same base model —
  do not pass a different `model`; the separation is role and context, not
  model.
- Escalation is per call, by risk (see `.agents/rules/risk-routing.md`):
  ambiguous/design → keep it in this session (Planner); core logic or guarded
  files → `adversary` + `hard-rule-auditor` on the branch; mechanical,
  fully-specified step → `routine-runner`; raw pulls → `data-fetcher`.
- Foreground agents when the result blocks the next step; background for
  independent work, then `wait_agents`.

## CODA container notes

- Runtime: Node (v26) at `C:\Program Files\nodejs\node.exe` (not on PATH —
  use the full path or add it). Tests and the generator run with Node.
- Everything lives in the repo; commit before you stop.
- Worktrees under `.wt/` are local scratch; merge or discard before the turn
  ends; never push them.
- Hooks configured in `.coda/settings.json` run for every session in this
  repo; they are policy, not suggestions. If a hook blocks you, fix the
  cause or record a bypass with a reason — never disable a hook.

## Generated agents

`.coda/agents/*.md` are GENERATED by `tools/gen_agents.py` from
`.agents/roles/*.md`. Edit the role, re-run the generator, commit both. A
policy test fails on drift.
